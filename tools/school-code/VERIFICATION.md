# Verification — School Code 0.19.3

- Version 0.19.3 adds the `generate_image_asset` Workspace tool, which routes image generation through the logged-in Chrome session when a workflow has no native image tool. Version 0.19.0 adds a local Git CLI tool family with structured repository status, diff, history and branch reads, approval-gated stage/commit/fetch/fast-forward pull/push, secret-path protection, and normal `NOT_A_REPOSITORY` results. Missing workspace paths now return `PATH_NOT_FOUND` structured results, and expected workflow path errors no longer abort the entire run.

- Version 0.6.0 adds read-only Notion tools, allowlisted Unity CLI tools, a loopback Unity Editor bridge template, and project Skill loading. Version 0.6.2 adds standard `.agents/skills` loading with `.school-code/skills` overrides. Version 0.7.0 adds an approval-gated project shell harness with bounded synchronous and background tasks. Version 0.7.1 adds optional per-session context compaction with configurable thresholds. Version 0.8.0 adds a local MCP catalogue and registry for Workspace, Notion, Unity, Blender, Unreal, and custom HTTPS MCP connections. Version 0.8.1 moves the Unity CLI path fallback to extension state and exposes relay connection errors in the panel. Version 0.8.2 adds the bcsd-nai default relay choice and a custom relay option. Version 0.8.3 clarifies the separate Unity CLI path and Editor bridge actions in the panel. Version 0.9.0 adds one-click Unity Editor bridge installation, token provisioning, Editor launch, and loopback detection. Version 0.5.0 adds Codex-style separated chat sessions and per-session approval modes. Version 0.4.0 made the connected project an on-demand workspace tool target with binary asset metadata, project instruction discovery (`AGENTS.md`, `CODEX.md`, `CLAUDE.md`), and an expanded MCP schema.
- All automated tests pass, including optional context compaction summaries and threshold handling, shell command workspace/timeout/output limits, background task status/output/cancellation, Notion pagination/error handling, Unity CLI path and target restrictions, Unity Editor bridge authentication, standard `.agents/skills` loading with `.school-code/skills` overrides, session migration/isolation, workspace metadata/instruction tools, attachment snapshots/limits, sensitive and binary file rejection, unsaved-file rejection, project switching, folder selection, image download/Base64 handling and the coordinator's actual outgoing chat payload.
- `CLUB-SHARING.md` documents the token boundary and BCSD account pairing flow. Static-token relay compatibility remains available. It does not contain real server URLs or credentials.
- Shell commands begin in the connected project and are approval-gated, but they still run with the current Windows user's OS permissions; the extension does not provide a kernel-level sandbox.

- Version 0.9.1 adds read-only public Notion link support: a `notion.site`/`notion.so` link can be registered without an Integration Secret, searched, fetched, and expanded through the existing Notion tools. Version 0.9.2 keeps the full setup view in the sidebar while collapsing setup cards in short bottom-panel views so the conversation and composer remain usable. Version 0.9.3 collapses the MCP catalogue by default so its rows no longer consume the conversation's vertical space. Version 0.9.4 keeps model and agent selectors visible while moving response, approval, and compaction controls into a collapsed advanced settings row, and reduces the default composer height. Version 0.10.0 adds BCSD account pairing, hashed per-user tokens, per-workspace worker isolation, token revocation, and automatic MCP auth JSON copying. Version 0.14.0 keeps one browser pairing request in flight, polls approval without waiting for a notification to close, allows an approved pair to retry token delivery after a lost status response, and softens chat-panel wheel scrolling while preserving the reader's position during streaming. Browser and Workspace connect actions also ignore rapid repeat clicks while an existing request is still opening or awaiting approval. The existing browser, protocol, coordinator, connector and MCP round-trip checks remain covered by the test suite. The 0.14.0 package is rebuilt as `school-code-0.14.0.vsix`; the current automated test count is reported by `npm test`.
- Generated image attachments are now downloaded through the logged-in Chrome worker and rendered as data-URI previews in the VS Code panel. Preview bytes remain in extension memory and are not written into saved sessions.
- Version 0.14.0 adds workflow-agent routing over `/agents/{id}/workflow/run`, streamed run/node/token status with a persisted step timeline, and the approval-gated `create_directory` Workspace tool. Tests cover workflow SSE handling, nested folder creation, existing folders, and unsafe paths.
- Version 0.15.0 adds session-scoped Codex-style `/goal` commands (`/goal`, `/goal status`, `/goal done`, `/goal clear`) and includes active goals in model and workflow prompts. The Unity Editor bridge now selects an available loopback port from 18777 onward, records it per project under `.school-code/unity-editor-ports`, and lets the extension discover that port automatically. The automated suite contains 37 passing tests.
- Version 0.15.1 creates the starter root `AGENTS.md` automatically during the first `workspace_info` discovery without an approval prompt, while preserving the no-overwrite rule for existing instruction files.
- Version 0.16.0 adds read-only visual asset inventory and `read_image` MCP image content for PNG/JPEG/GIF/WebP/SVG/ICO files, including dimensions, hashes, Unity texture `.meta` values, safe SVG checks, a 16 MiB limit and bounded in-memory reuse.
- Version 0.17.0 adds Unity Scene/Game image capture, model previews and lightweight FBX/OBJ/GLB/GLTF metadata, Play Mode and Console controls, project status/build settings, Animator and Material helpers, prefab and GameObject editing actions, and MCP image content for Unity captures.
- Version 0.18.0 adds a built-in Figma MCP catalogue entry with the official remote endpoint, OAuth guidance, and per-connection secret handling.
- Version 0.3.0 replaces the bookmarklet with a bundled Manifest V3 Chrome connector, based on the image connector at upstream commit b98345b. The two connectors use separate ports and worker names.
- Actual school chat through the new Chrome connector needs one-time Chrome extension installation and a logged-in school tab. Live Chrome installation/connection has not been verified automatically.
- School-to-MCP-to-VS Code live round trip still needs an externally reachable HTTPS relay and the school agent's MCP configuration.
- Docker deployment files are provided; Docker image execution has not been verified because the local Docker daemon was unavailable.
