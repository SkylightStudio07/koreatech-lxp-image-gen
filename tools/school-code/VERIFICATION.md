# Verification — School Code 0.8.1

- Version 0.6.0 adds read-only Notion tools, allowlisted Unity CLI tools, a loopback Unity Editor bridge template, and project Skill loading. Version 0.6.2 adds standard `.agents/skills` loading with `.school-code/skills` overrides. Version 0.7.0 adds an approval-gated project shell harness with bounded synchronous and background tasks. Version 0.7.1 adds optional per-session context compaction with configurable thresholds. Version 0.8.0 adds a local MCP catalogue and registry for Workspace, Notion, Unity, Blender, Unreal, and custom HTTPS MCP connections. Version 0.8.1 moves the Unity CLI path fallback to extension state and exposes relay connection errors in the panel. Version 0.5.0 adds Codex-style separated chat sessions and per-session approval modes. Version 0.4.0 made the connected project an on-demand workspace tool target with binary asset metadata, project instruction discovery (`AGENTS.md`, `CODEX.md`, `CLAUDE.md`), and an expanded MCP schema.
- All automated tests pass, including optional context compaction summaries and threshold handling, shell command workspace/timeout/output limits, background task status/output/cancellation, Notion pagination/error handling, Unity CLI path and target restrictions, Unity Editor bridge authentication, standard `.agents/skills` loading with `.school-code/skills` overrides, session migration/isolation, workspace metadata/instruction tools, attachment snapshots/limits, sensitive and binary file rejection, unsaved-file rejection, project switching, folder selection, image download/Base64 handling and the coordinator's actual outgoing chat payload.
- `CLUB-SHARING.md` documents the token boundary and the current single-worker relay limitation. It does not contain real server URLs or credentials.
- Shell commands begin in the connected project and are approval-gated, but they still run with the current Windows user's OS permissions; the extension does not provide a kernel-level sandbox.

- The existing browser, protocol, coordinator, connector and MCP round-trip checks remain covered by the test suite. The 0.8.1 package is rebuilt as `school-code-0.8.1.vsix`; 30 automated tests pass.
- Generated image attachments are now downloaded through the logged-in Chrome worker and rendered as data-URI previews in the VS Code panel. Preview bytes remain in extension memory and are not written into saved sessions.
- Version 0.2.0 replaces the bookmarklet with a bundled Manifest V3 Chrome connector, based on the image connector at upstream commit b98345b. The two connectors use separate ports and worker names.
- Actual school chat through the new Chrome connector needs one-time Chrome extension installation and a logged-in school tab. Live Chrome installation/connection has not been verified automatically.
- School-to-MCP-to-VS Code live round trip still needs an externally reachable HTTPS relay and the school agent's MCP configuration.
- Docker deployment files are provided; Docker image execution has not been verified because the local Docker daemon was unavailable.

The browser automation helper could not establish the current Chrome URL and stopped. This does not establish that the extension's browser bridge is failing; that path has not yet been connected live.
